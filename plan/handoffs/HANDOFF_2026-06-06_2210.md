## What was done this session

- **Cleared the NavMesh blocker (Unreal content).** `NavMeshBoundsVolume` had **Scale Z = 1** (~200 cm tall) → <100 cm headroom over the road, below Recast's ~144 cm AgentHeight → no walkable mesh, so `SimpleMoveToLocation` silently no-op'd. Fix: user raised **Scale Z → 10** (~2000 cm tall) and re-centered it above the floor, rebuilt (green appears on P), saved the level. Also learned per-avatar: an NPC on grass/dirt or "too low" has no mesh under it and won't move regardless — Maren had to be repositioned onto green.
- **Found & fixed the `GWorld` actor-duplication bug (C++).** The plugin resolved actors via `GWorld`, which flips between the editor and PIE worlds during Play → every command/read randomly hit one of two duplicate actors (live PIE vs frozen editor copy). This was the root cause of the previous session's "move returns success but avatar never translates," `AIState=moving` vs status `idle` mismatch, and z flip-flopping (`88.17`/`188.17` editor vs `90.32` PIE). Fix: added `FUnrealMCPCommonUtils::GetGameWorld()` (walks `GEngine->GetWorldContexts()`, prefers `EWorldType::PIE`/`Game`, falls back to `GWorld`) and switched the **runtime hot-loop** lookups to it: `UnrealMCPCharacterCommands.cpp` (both resolvers + `get_nearby_actors`) and `UnrealMCPCameraCommands.cpp` (named lookup + first-CameraCaptureActor fallback). Left Editor/Attachment commands on `GWorld` (they should target the editor world). **Required an Unreal recompile + `/mcp` reload** — done.
- **Verified the fix:** three back-to-back `get_character_location` reads returned the *same* live PIE value (no more frozen duplicate). Direct move test: Dufus translated `-9850 → -9589` with `ai_state:moving` reading consistently on the live actor.
- **Ran explore mode live (Maren).** Clean `spatial_map.json`, `start_simulation(mode="explore", tick_seconds=10, active_agents=["maren"])`. She walked west cell-by-cell (`-14,-2` → `-23,-2`), `cells_visited` climbed 1→2→4→…, grounded z≈90 throughout, perceiving real landmarks (JOB OFFERS sign, red barn, water tower, corn field, mobile/trailer homes, utility poles, "white sphere" debug asset). ## Decisions locked in this session

- **NavMesh volumes must clear the floor by > agent height** — a thin volume builds no mesh; this is content, not code. Avatar must stand on green (on mesh), never floating/too-low.
- **MCP runtime commands resolve the PIE world via `GetGameWorld()`, not `GWorld`** — editor-authoring commands stay on `GWorld` deliberately. (This also explains why `find_actors_by_name`/`get_actors_in_level`, which are Editor commands, return empty/editor results during PIE — known, not a bug.)
- **Delete `spatial_map.json` after any broken-movement run** — false `blocked` marks accumulate and poison the frontier set (a single broken window blocked all 8 neighbors → "no frontier" → idle).

## Open questions

- **`mark_blocked` fragility (top of next-session list)** — the explorer treats a move that finds *no path / never started* the same as "reached but obstructed," permanently blocking the frontier. Should distinguish the two (e.g. only block after the avatar actually arrives near the cell and is then obstructed; on a no-path/timeout, retry or skip without blocking).
- **Sim-owned teleport onto NavMesh at startup** — planned but not built. Would make the avatar self-recover from an off-mesh spawn instead of needing a manual `End`-key drop. Needs a known-good ground projection (project actor location to nearest navmesh point).
- **Diff-gate leaves cells unlabeled** — fast back-to-back ticks skip perception, so several traversed cells have empty `landmarks`. Harmless but sparse; revisit cadence vs. coverage.
- **Label canonicalization (still deferred)** — Gemini emits variants ("mobile homes"/"mobile home"/"trailer homes", "red barn"/"red barn with white trim") stored as separate tags; needs a place-promotion/clustering step.
- **Move socket timeout** — was intermittent last session; not seen this session after the world fix. Watch whether it recurs; if so make the bridge treat a move timeout as "issued, not failed."
