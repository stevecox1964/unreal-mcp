### #96, concretely

* **`Python/agent_runtime/survey_mission.py`** (new, pure — no bridge, no LLM, no I/O, mirroring
  `cell_sweep.py`): `ring_cells` orders every grid cell center-out (Chebyshev rings from the
  world-bounds centre cell, clockwise from north, ties by (col,row) so a world always surveys in
  the same order). `next_target` skips a `done` set and an `unreachable` predicate and returns
  `None` only when every cell is answered. **The skip is the feature** — as coverage grows the
  first un-done cell in ring order *is* the frontier, however far away, which is the user's "look
  past already-surveyed grids" requirement expressed as a data structure rather than a prompt.
  Sanity-run offline: centre first, then the ring clockwise from north; skips confirmed.
* **`Agent.mission`** (`agent.py`) — reads `state.json` `"mission"`. `"survey"` opts an APC into
  mission mode; empty (default) is the ordinary cognitive loop. **Only Dufus is opted in**
  (`d3c7362`); Maren and every personality APC are untouched.
* **`PlaceDB.swept_cells()`** — the done set, one query.
* **The mission bucket** in `_tick_impl`, after the sweep and walk buckets: `_mission_wants_tick`
  → `_pulse_mission`, deterministic and bridge-only. It calls `_mission_next_target` and offers
  the cell as an ordinary **survey interruption**. `_offer_survey_interrupt` grew
  `target` / `source` / `reason` parameters (default behaviour unchanged) — so the mission's whole
  commute, including the far-cell `goto_center` leg and the `_survey_travel_is_wedged`
  abandon path, rides existing machinery. Nothing was forked.
* **The checkpoint is `_force_next_decide`.** A finished sweep already files that debt (SR44's
  fix); `_mission_wants_tick` returns False while it stands, so the APC falls through to the
  ordinary observe/perceive/decide path **exactly once per surveyed cell**. One LLM call per cell,
  no new prompt machinery. `_mission_fact` + `_mission_text` (`llm_router.py`) add one section:
  coverage, next target, and "spend this decision on MEANING — name, refuse, observe; do NOT
  order travel".
* **Start placement.** `_mission_start_placement`, called once in `start_simulation` **after** the
  normal start-transform reposition: teleport the APC to the centre of a **swept** neighbour cell
  of its first target, preferring one with `_GOOD_FOOTING` ground somebody actually stood on. No
  swept neighbour (fresh world) or already within one cell → **no teleport**. Mid-run there is no
  teleport at all.
* **Fail-loud paths:** mission complete logs `SURVEY MISSION COMPLETE` as a warning, once, and
  reports `action: "mission_complete"`; a tick that produces no step logs a warning and returns
  `mission_no_step` rather than idling silently.

## Decisions locked in this session

* **A `measured` patch never merges with a `stated` one, and is capped at 300 cm.** They are
  different claims with different TTLs; merging them is what let one circle wall off a pocket.
* **Only `measured` radii are clamped.** The nine legacy 450 cm `stated` patches were left as
  they are — a stated judgement is the mind's, and shrinking it is a separate decision.
* **Mission mode is an opt-in role, not a global controller.** `"mission": "survey"` in
  `state.json`. Personality APCs keep the full cognitive loop and facts-not-blockers
  ([[feedback_facts_not_blocking]]); mission mode is deliberately a *different authority regime*
  and says so in the code and the backlog.
* **The mission checkpoint prompt is allowed to steer** ("do not order travel"). That is the one
  documented exception to facts-only, scoped to APCs that opted in.
* **Teleport at run start only; walk for everything else.** Covered ground is cheap now (grown
  steps on proven ground) and walking it still feeds the VLM corpus
  ([[project_dufus_vlm_training_corpus]]). A mid-run teleport would break the body's own memory
  story; a start placement is just driving to the job site off-camera.
* **Nothing was forked from the locomotion stack.** Mission mode chooses *targets*; travel stays
  on `route_planner` cell paths and walk plans — the same road an APC uses for a named-place
  `walk_to`, which is what keeps the user's future "where is Don's Donuts → give me cells to
  traverse" request served by one system.
* **The plan doc's Phase-1 open decisions ran on their stated defaults:** unreachable ring cell →
  skip and continue; checkpoint stays on the current decision model; Maren gets no mission.
