## What was done this session

- **New `Python/agent_runtime/ollama_adapter.py`** — single adapter serving both callers. Uses Ollama's native `/api/chat` so it can disable "thinking" (`think:false`) and force JSON (`format:"json"`) — qwen3.5 is a thinking model and stray `<think>` blocks corrupt the short JSON both callers parse (stripped defensively too). Supports an optional image (vision). Sends `keep_alive` (default `-1`) so the model stays resident for the whole run. ## Decisions locked in this session

- **One multimodal model for both roles.** `qwen3.5:4b` has `vision` capability (user verified on real observation images), so a single model serves decision + perception. No separate text/vision split needed.
- **Native `/api/chat`, not the OpenAI-compat endpoint.** Only the native API cleanly exposes `think:false`, `format:"json"`, and `keep_alive`.
- **`keep_alive=-1` keeps qwen resident for the whole run.** Ollama's 5-min default was unloading the model between sparse (diff-gated) ticks, causing the "model reload" the user saw. Tunable via `OLLAMA_KEEP_ALIVE`.
- **PIE logging only from sequential phases.** The single-socket connection is not thread-safe; phase 2 (perceive+decide) runs in parallel and must never call the bridge.
- **Global `.env` switch, not per-agent.** Both agents are tier 2 with no per-agent overrides, so flipping `LLM_PROVIDER`/`VISION_PROVIDER` covers both. Per-agent override via `state.json` still exists.
