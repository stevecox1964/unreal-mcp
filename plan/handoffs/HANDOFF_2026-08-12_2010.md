## Decisions locked in this session

- **Centroid-then-fan-out was considered and rejected** for #73. The centroid of a mapped blob is always
  *inside* it — SR41's is (6, 5.4) and Dufus woke standing on it — so "walk to the centroid" is a no-op
  or a walk backwards, and "fan out" is the thing already being done badly. The ribbon is created one
  direction-choice at a time; that is the only place it can be fixed. The user's *diagnosis* (snake, not
  blob) was right and is what the fix serves.
- **The frontier list shows one cell per bearing, not the N nearest.** Sorting by distance alone fills a
  short list from whichever side of the blob happens to be closest — the same "everything points that
  way" input that drew the line. A truncated list that all points one way is not a choice.
- **#73 and #74 stay facts, not overrides.** No sixth code-over-LLM override;
  [[feedback_facts_not_blocking]] holds. If Dufus reads a listed frontier cell and still walks east,
  that is data about the model and SR42 will have measured it.
- **#75 is not #71.** The names are identical — it is cell quantization, not naming. Separated because
  the fix is different and #71 remains open on its own terms.
- **Arrival was already correct and was reused, not changed.** `_at_scheduled_place` already tests the
  world-space extent box, so Maren was rightly judged *at* her truck (120 cm off a 450 cm half-box)
  while the map disagreed about the cell. #75's same-place test is that same box test.
- **The merge keeps the authored row, else the oldest** — `places.json` is ground truth and a runtime
  observation must never overwrite it.
- **SR41 counts as a good run.** Locomotion is now a background service that is behaving; the user
  confirmed Maren staying put is expected and correct. Grading stays on Maren's day and on social
  contact, per the prior session's reset.
