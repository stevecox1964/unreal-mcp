## Decisions locked in this session

- Use an editable JSON agenda, not a general-purpose behavior tree.
- Minimum authored task fields are `id`, `start`, `end`, `place`, `objective`, and `completion.type`.
- Keep authored agenda separate from runtime task state. Runtime states are `pending`, `active`,
  `interrupted`, `completed`, and `blocked`, with timestamps and grounded completion evidence.
- First-slice completion policies are `arrive_at_place`, `time_block_ends`, and
  `time_or_llm_confirmed`; unknown policies fail validation.
- The deterministic executive advances and resumes tasks; the LLM retains in-character choice over how
  to perform the active objective.
- Unknown/stale community surveys and direct chat suspend the exact active task and resume it unless an
  explicit logged reprioritization occurs.
- Prompt context includes authoritative **Today so far**, **Right now**, and **Next** sections. Existing
  relevance-selected episodes remain memory but are not the completion ledger.
- After arriving at a named destination, deterministic completion activates the next eligible activity;
  the model does not invent what comes next. Free goal behavior begins only after eligible agenda work is
  complete, apart from bounded survey/chat interruptions.
- The existing APC editor is preserved and made discoverable through an **APCs** navigation entry.
