# Dream — The take-up-slack autonomous loop (deepen backlog #4)

**When:** 2026-06-25 11:49 CDT · **Iteration:** 4 · **Scope:** planning only
**Format:** "here is what I'd do" — each action is subagent-ready (Goal / Files / Steps / Done-when / Deps).

**Context (1 line):** backlog #4 wants Claude in a self-paced `/loop` that works the backlog unattended
(branch → failing test → implement → run tests → commit on green) until credits cut it off, then resumes
from the handoff. The repo already fits this *better than #4 assumes*: tests here are **standalone offline
scripts** under `Python/scripts/**/test_*.py` (14 of them) that **stub Unreal entirely — no network, no
PIE, no editor** (e.g. `test_pacing_and_reset.py`), run via `.venv\Scripts\python.exe scripts\...\test_x.py`.
That offline-stub surface *is* the loop-safe zone. The gaps are operational: no aggregated green signal, no
preflight gate, no written run-contract the loop reads each start. This iter turns #4 from intent into a
runnable harness. (Note: iter-2's runner `sim_runner.py`/`factory.py` still doesn't exist — #3 is unbuilt,
so anything touching the live sim stays out of scope here.)

### Action 4.1 — Write the loop run-contract the loop reads on every start
**Goal:** a single committed doc that encodes #4's guardrails as an explicit, checkable contract — the loop's "constitution," not prose buried in backlog.
**Files:** new `plan/autonomous_loop.md`; link it from `plan/backlog.md` #4 and `plan/handoffs/LATEST.md`.
**Steps:**
1. State the **allowed surface**: Python-only, offline, test-verifiable; tests follow the existing standalone-script + Unreal-stub convention (no pytest introduction, no live sim).
2. State **hard NOs** (verbatim from #4): never C++ / Blueprints / UMG / `.env`; never start the sim or need PIE; never push.
3. State **stop conditions**: tests red after ~2 fix attempts → stop; needs editor/rebuild/design choice → skip+log; ambiguous → skip+log.
4. State the **per-item cycle**: branch → failing test → implement → run aggregator (4.3) → commit on green → update backlog + handoff (4.5).
**Done when:** the doc exists and a fresh session could follow it without re-deriving the rules. **Deps:** none. **Subagent-safe:** yes (doc only).

### Action 4.2 — Preflight gate: refuse to start on an unsafe state
**Goal:** stop the loop from compounding errors on a dirty/wrong base (Global Rule #10 "checkpoint every step").
**Files:** new `Python/scripts/loop/preflight.py` (standalone, offline).
**Steps:**
1. Assert: working tree clean, **on a dedicated loop branch** (not `main`), and the test aggregator (4.3) is **green** as a baseline.
2. Exit non-zero with a one-line reason if any check fails; print "PREFLIGHT OK" + branch + baseline test count on success.
**Done when:** running it on a dirty tree or on `main` exits non-zero with the reason; on a clean loop branch with green tests it passes. **Deps:** 4.3. **Subagent-safe:** yes.

### Action 4.3 — Test aggregator: the single green/red signal
**Goal:** one command that discovers and runs every offline test and returns one pass/fail — there's no pytest config, so the loop currently has no aggregate signal.
**Files:** new `Python/scripts/run_tests.py`.
**Steps:**
1. Discover all `Python/scripts/**/test_*.py`, run each with the venv interpreter as its own process (they're `__main__`-style, Unreal-stubbed, offline).
2. Capture exit codes; print a per-file PASS/FAIL table + totals; exit non-zero if any failed.
3. Support `--only <glob>` so the loop can run just the test it's iterating on, then the full suite before commit.
**Done when:** `run_tests.py` reports all 14 current tests green and returns 0; flipping one to fail makes it return non-zero and name the file. **Deps:** none. **Subagent-safe:** yes.

### Action 4.4 — First loop-safe target, spec'd failing-test-first: #1 named-place resolver
**Goal:** prove the harness on the best self-contained target — `walk_to <place-name>` resolving to a PlaceDB cell-center instead of idling (backlog #1; today it short-circuits to idle in `unreal_bridge.execute_action`).
**Files:** new `Python/scripts/agent_runtime/test_place_resolver.py` (offline, stubs Unreal like its siblings); implement in `Python/agent_runtime/` (resolver over `place_db`).
**Steps:**
1. **Failing test first:** given a PlaceDB with a named cell ("village square"), `resolve_place("village square")` returns its cell-center location; unknown name returns a clear not-found (not a crash).
2. Implement the resolver against `PlaceDB`; wire `walk_to` to call it and navigate when resolved (idle only on genuine not-found).
3. Run via the aggregator; commit on green.
**Done when:** the new test passes through `run_tests.py` and `walk_to "village square"` produces a navigation target in the offline test. **Deps:** 4.3; informs backlog #1. **Subagent-safe:** yes (offline + test). *(If wiring `walk_to` needs live-sim verification, land the resolver + unit test only and log the integration step.)*

### Action 4.5 — Recoverability step: keep handoff + backlog current as the loop runs
**Goal:** the loop is only resumable because the handoff/backlog stay fresh — #4 says there's *no* "credits draining" signal, so state must be written continuously, not at the end.
**Files:** `plan/handoffs/LATEST.md` (update each green commit), `plan/backlog.md` (check items off as they land).
**Steps:**
1. After each green commit, append to `LATEST.md`: what landed, the commit hash, what's next, any skipped+logged items.
2. Check off / annotate the backlog item just touched.
3. On any stop condition (4.1), write a final "stopped because X, resume at Y" handoff line.
**Done when:** at any point mid-loop, `LATEST.md` alone tells the next session exactly where to resume. **Deps:** 4.1. **Subagent-safe:** yes (the `/handoff` skill already does most of this).

### Decision needed (human, not subagent)
- **Cost/enablement:** #4's own note says unattended **cloud** runs burn paid credits and defeat the "use unspent credits" aim — local/hybrid inference is the real enabler. Run the loop on cloud now for the *Python-build* work (cheap, no per-tick inference) and keep **live-sim** work for when local models land? *(Recommend: yes — the build/test loop doesn't call the LLM, so it's cheap; only running the sim is costly.)*
- **Kickoff:** dedicated `/schedule` routine after credits refresh vs manual `/loop` start? *(Recommend: manual to start, automate once trusted.)*
- **Branch policy:** one long-lived `auto/loop` branch, or a fresh branch per backlog item? *(Recommend: branch per item — smaller, reviewable, easy to drop a bad one.)*
- **Merge gate:** does a human review each loop branch before it reaches `main`, or may the loop fast-forward trivial green changes? *(Recommend: human reviews — "never push unattended" implies never auto-merge either.)*
