# Dream — Decouple Claude/MCP from the world builder

**When:** 2026-06-24 23:27 CDT · **Iteration:** 2 · **Scope:** planning only
**Format:** "here is what I'd do" — each action is subagent-ready.

**Context (1 line):** the coupling is one line — `unreal_sim_server.py:417` `mcp.run(transport='stdio')`.
The MCP server is a **stdio subprocess of Claude Code**, and the `AgentManager` singleton that runs
the async sim `_loop` lives *inside* it → close Claude, sim dies. The `UnrealBridge` (TCP 55557) and
the web UI's direct socket (`web_ui/unreal_client.py`) are already Claude-independent. Goal: move the
sim runtime into a **standalone process**; make MCP + web_ui *clients* that attach to it. (Backlog #3.)

---

### Action 2.1 — Factor AgentManager construction into a shared factory
**Goal:** one builder both the MCP server and a standalone runner can call (kills the "only built inside MCP" coupling).
**Files:** new `Python/agent_runtime/factory.py`; edit `unreal_sim_server.get_agent_manager` (lines 218–235).
**Steps:**
1. Move the construction block (worlds_dir, `UnrealBridge`, `LLMRouter`, `MemoryStore`, `AgentManager`) into `build_agent_manager()`.
2. `get_agent_manager` calls the factory; behavior unchanged.
**Done when:** MCP server still works; factory importable + unit-tested standalone.
**Deps:** none. **Subagent-safe:** yes.

---

### Action 2.2 — Standalone sim-runner entrypoint
**Goal:** run the sim loop as its own process, no MCP/Claude involved.
**Files:** new `Python/sim_runner.py`.
**Steps:**
1. Build the manager via `build_agent_manager()` (2.1); `asyncio.run` start + serve.
2. Handle SIGINT/SIGTERM for clean stop; log to its own file.
**Done when:** `python Python/sim_runner.py` ticks agents against Unreal with Claude Code closed.
**Deps:** 2.1. **Subagent-safe:** yes.

---

### Action 2.3 — Control surface on the runner (start/stop/status over localhost HTTP)
**Goal:** let other processes control/inspect the running sim instead of hosting it.
**Files:** `Python/sim_runner.py` (embed a small FastAPI/uvicorn on a localhost port).
**Steps:**
1. Endpoints mirroring `simulation_tools`: `POST /start /stop /pause /resume`, `GET /status /agents`, `POST /tick`.
2. Each delegates to the in-process `AgentManager`. JSON in/out.
**Done when:** `curl localhost:<port>/status` returns live sim status while `sim_runner` runs.
**Deps:** 2.2. **Subagent-safe:** yes (IPC choice = decision below).

---

### Action 2.4 — Make MCP simulation tools thin clients of the runner
**Goal:** Claude/MCP *attaches* to the running sim; closing Claude no longer stops it.
**Files:** `Python/tools/simulation_tools.py`.
**Steps:**
1. Replace direct `get_agent_manager()` calls with HTTP calls to the runner's control API.
2. If no runner is reachable, return a clear "no sim runner running — start it via web_ui/CLI".
**Done when:** with `sim_runner` up, MCP `get_simulation_status` returns its status; closing Claude leaves the sim ticking.
**Deps:** 2.3. **Subagent-safe:** yes.

---

### Action 2.5 — Bridge to web_ui (handoff to theme ③)
**Goal:** web UI can start/stop/inspect the standalone sim (it becomes the controller).
**Files:** `Python/web_ui/unreal_client.py` (add a `sim_runner_client`), `web_ui/main.py`.
**Steps:**
1. Add client calls to the runner control API (2.3).
2. Surface start/stop/status buttons in the UI.
**Done when:** web UI starts the sim with Claude Code closed.
**Deps:** 2.3. **Subagent-safe:** yes. *(Overlaps theme ③ — flesh out there.)*

---

### Decision needed (human, not subagent)
- **IPC:** localhost HTTP (FastAPI) vs raw socket vs named pipe? *(Recommend HTTP — web_ui already speaks it, trivial to curl/debug.)*
- **Auto-spawn:** should MCP tools auto-launch `sim_runner` if none is running, or require it be started separately? *(Auto-spawn re-couples lifetime to Claude — recommend require-separate.)*
- **Unreal socket ownership:** the bridge is single-socket / not concurrency-safe. If `sim_runner` + web_ui + MCP all hit 55557, they contend. Who owns it — runner exclusively, others go through the runner? *(Recommend: runner owns Unreal; web_ui/MCP read sim state from the runner, not Unreal directly.)*
- **Multiplicity:** one runner per machine (fixed port) or one per world?
