### Action 3.2 — Config store: read/write `.env`-backed settings in one place
**Goal:** a single typed accessor that loads current config and writes changes back atomically, reusing the existing reload path so no restart is needed.
**Files:** new `Python/agent_runtime/config_store.py`; reuse `_ENV_PATH` + `load_dotenv(override=True)` semantics from `llm_router._reload_env`.
**Steps:**
1. `read_config() -> dict` returns the known keys (`LLM_PROVIDER`, `VISION_PROVIDER`, `LLM_MODEL`, model/key names) with safe defaults — **never** return secret values (return "set"/"unset" booleans for `*_API_KEY`).
2. `write_config(updates: dict)` validates keys against an allowlist, rewrites `.env` preserving unlisted lines/comments, then triggers a reload.
3. Unit-test round-trip on a temp `.env`; assert comments + unknown keys survive and secrets are never echoed back.
**Done when:** `write_config({"LLM_PROVIDER":"ollama"})` flips the value on disk, preserves the rest of `.env`, and a subsequent `read_config()` reflects it.
**Deps:** none. **Subagent-safe:** yes (Python + test). *(Decision: settings persistence target — `.env` vs new `config.json`; see below.)*

### Action 3.3 — Settings page in the web app (GET form + POST save)
**Goal:** manage config through the UI instead of hand-editing `.env`.
**Files:** `Python/web_ui/main.py` (add `GET /settings` + `POST /settings`), new `templates/settings.html`, nav link in `base.html`.
**Steps:**
1. `GET /settings` renders current values from `config_store.read_config()` (secrets shown as set/unset only, never the value).
2. `POST /settings` validates + calls `config_store.write_config()`, flashes success/error, redirects back.
3. Add a "Settings" nav link alongside the existing worlds/agents nav.
**Done when:** editing a value in the form and saving updates `.env` and the live process picks it up without a restart.
**Deps:** 3.2. **Subagent-safe:** yes (Python/Jinja + the app already runs Claude-independently).
